## 后续操作边界

测试服务日常检查：

```bash
sudo docker compose -p frappe-test \
  -f /opt/tsuite-deploy/frappe-test/compose.yml ps
sudo python3 /opt/tsuite-deploy/frappe-test/verify.py
```

更新测试版本时只操作 `frappe-test` 和 `tai_test`，备份测试库后更新其固定镜像、迁移并复验；
不要直接套用写死 `frappe-customer` 的原 customer playbook，也不要修改演示 inventory 的镜像锁。
首次复制脚本发现同名测试库时会拒绝覆盖，不应重新执行脚本来升级或重置已有测试数据。

如需停止测试环境，使用其独立 Compose 的 `stop` 和 `tai-test-frpc.service`；不执行带 volume
删除选项的命令。移除 HTTPS 入口时恢复对应 Caddy import，并先验证再 reload。
